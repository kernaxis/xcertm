# CI and releases

GitHub Actions uses the Go version declared in `go.mod`, including the preferred
Go 1.26.11 toolchain. Tests use local fixtures and need no Cloudflare, OVH, ACME
account, or NAS credentials. The workflows target `main`.

## Workflows

| Workflow | Events and checks |
| --- | --- |
| `ci.yml` | Pull requests and pushes to `main`, manual runs, and release reuse: formatting, vet, staticcheck/ineffassign, tests with coverage, and race tests. Coverage artifacts are retained for seven days. |
| `security.yml` | Pull requests, main pushes, manual/reusable runs and daily vulnerability checks: reachable Go vulnerabilities, actionlint, zizmor, and dependency review on pull requests. Release calls scan all four target architectures; ordinary runs scan amd64. |
| `codeql.yml` | Pull requests, main pushes, manual runs and a weekly Go CodeQL analysis using a manual build. |
| `release.yml` | A version tag push or manual release request: validate the version/commit, reuse CI and security checks, build all targets, then create a draft release with archives and checksums. |

Dependabot checks Go modules and GitHub Actions weekly. It does not automatically
merge changes. Unknown or unreviewed runtime license families stop packaging.

CI has no standalone binary build or packaging step. Distributable binaries and
archives are built only by Release. Tests/lint compile the code they analyze;
CodeQL separately performs the compilation required for its analysis.

Actions are pinned to full commit SHAs. Checkout does not retain credentials.
Validation/build jobs have read-only repository permissions; only draft
publication gets `contents: write`, and only CodeQL gets `security-events: write`.
Pull requests do not receive release credentials or publish artifacts as releases.
Superseded pull request checks can be canceled; releases are never automatically
canceled. Release builds do not restore caches from other workflow runs.

Two narrow zizmor annotations retain the standard same-commit relative reusable
workflow syntax: actionlint currently rejects the newer `$/` form. Other workflow
security checks remain enabled.

The repository must allow Actions, dependency graph/review and CodeQL code
scanning. The repository is public; private forks may need additional GitHub
licensing for the security features. Workflows use the automatically supplied
`GITHUB_TOKEN`; no custom publication secret is required. CodeQL runs require
GitHub's hosted tooling and cannot be reproduced by `go test` alone.

Builds download modules/toolchains through Go's configured services and tools
from GitHub/PyPI. Vulnerability checks require the public Go vulnerability
database at `vuln.go.dev`. A blocked database is an error, not a successful scan.

## Local checks

Use Go, Make and the pinned lint tools:

```sh
go install github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.15.0
go install golang.org/x/vuln/cmd/govulncheck@v1.9.0
go install github.com/rhysd/actionlint/cmd/actionlint@v1.7.12

make ci
make vulncheck
actionlint
```

Workflow security uses `zizmor==1.32.0`, installed in an isolated Python
environment, with `zizmor --offline .github/workflows`. Offline mode avoids
GitHub API lookups by the workflow auditor; it does not disable its local audits.
The optional Makefile invokes the same Go checks as the direct commands in the
README. `coverage.out` and `dist/` are generated files and are ignored by Git.

## Release contract

Accepted versions are `vMAJOR.MINOR.PATCH` and `vMAJOR.MINOR.PATCH-rc.N`, without
leading zeros. For example, `v0.1.0` and `v0.2.0-rc.1`.

Two entry points are supported:

- Push an existing version tag. The workflow verifies that it still refers to
  the triggering commit and that the commit belongs to `main` history.
- Run **Release** from the `main` branch in Actions and provide the desired tag.
  An existing tag selects its commit; a missing tag selects the triggering main
  commit. A missing tag is created only after CI, security and builds pass.

Every job checks out the validated commit. Before publication, the workflow
checks all four archives, generates/verifies `SHA256SUMS`, and rechecks the tag's
target. A moved or deleted existing tag fails. Existing releases or drafts are
never overwritten. Release notes are generated by GitHub, including for the
first release without a previous tag.

The result is a **draft**, not an automatically published release. Review its
notes/assets in GitHub before publishing it. `-rc.N` versions are marked as
prereleases. No server or NAS deployment is part of these workflows.

The installer and `xcertm update` discover only published stable releases.
Publishing a draft makes it eligible for discovery; merely creating the tag or
running Release does not. Both consume the existing archive names and
`SHA256SUMS`; no separate build or publication workflow is required. See
[installation and updates](installation.md).

## Binary archives

| Archive suffix | Target |
| --- | --- |
| `linux_amd64` | Linux x86-64, including Synology DS1522+. |
| `linux_386` | Linux 32-bit x86. |
| `linux_armv7` | Linux ARMv7 (`GOARM=7`); ARMv5 is not included. |
| `linux_arm64` | Linux AArch64. |

Names follow `xcertm_0.1.0_linux_amd64.tar.gz` for tag `v0.1.0`. Binaries are
statically built with `CGO_ENABLED=0`, `-trimpath`, and injected `main.version`.
The amd64 binary's version is checked before upload.

Each archive contains the binary, README, guides, example configuration, MIT
license, the self-contained `THIRD_PARTY_NOTICES.md` with complete license/NOTICE
texts, and a generated `THIRD_PARTY_LICENSES.txt` runtime inventory. No separate
directory of vendored license files is needed. Only dependencies compiled into XCertM are inventoried;
CI tools and their dependencies are not linked into the application. There is
no Lego dependency or unrelated source-license bundle.

To build an archive locally, install the packaging tool and run:

```sh
go install github.com/google/go-licenses/v2@v2.0.1
make package VERSION=v0.1.0 GOOS=linux GOARCH=amd64
```

Python 3 and tar are needed for packaging. The default output is
`dist/xcertm_0.1.0_linux_amd64.tar.gz`; `BUILD_DIR` can override the directory.
`make releases VERSION=v0.1.0` builds all four archives locally. This command
does not create a Git tag or GitHub release. The workflow generates the external
`SHA256SUMS` manifest after collecting all four archives.
